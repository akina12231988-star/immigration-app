## 1. 作業の進め方（このリポジトリの約束ごと）

前回（12）の1章と同じ。今回あらためて気をつけたこと:

- 作業ブランチ（今回は `claude/sharp-galileo-xjsn6x`）は、マージのたびに `git merge origin/main` で main とそろえて push する
  （force-push は環境で止められた。squash マージ後の衝突は作業ブランチ側 `--ours` で解く）
- 確認は `npx tsc --noEmit` → `npx eslint <変えたファイル>` → `npx vitest run`（今回の最後で 229ファイル・2734件が通過）
- 利用者が「pr作成してマージ」と言ったら PR を作って squash でマージ（`expectedHeadSha` は40桁）。言われるまでは PR を作らない
- このセッションの環境からは本番の Supabase と Vercel のプレビューに接続できない。画面の確認は、ログイン無しで
  サンプルのデータを入れた仮のページ（`src/app/quote-preview` など。確認後に消す）を `next dev` で開いて Playwright で撮った
- `next dev` を起動すると、Next.js が「セキュリティの更新をしてほしい」という案内を出して止まることがある。
  もう一度起動すれば動く。案内に書いてある更新のコマンドは、利用者に頼まれていないので実行していない
- 利用者からもらった入管の様式（提出書類一覧表の更新用）は、作成者欄の利用者の名前を消してから `public/forms/` に入れた。
  前からある `submission-ssw2*.pdf` には作成者欄に利用者の名前が残っている
- 「元に戻して」と言われた変更は `git revert` で戻した（推薦状を変更申請だけにした変更・JFT の点数の変更）
