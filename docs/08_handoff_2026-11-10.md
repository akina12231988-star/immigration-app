## 1. 作業の進め方（このリポジトリの約束ごと）

- 作業ブランチ: `claude/handover-2026-11-05-5oy4pf`（マージ後は `origin/main` から作り直して使い回す）
  ```
  git fetch origin main && git checkout -B claude/handover-2026-11-05-5oy4pf origin/main
  git push --force-with-lease -u origin claude/handover-2026-11-05-5oy4pf
  ```
- 確認（コミット前に毎回）: `npx tsc --noEmit -p .` → `npx eslint <変えたファイル>` → `npx vitest run` → `npm run build`
- 機能を足したら `src/lib/release-notes.ts` の `RELEASE_NOTES` の先頭に1件足す（画面の「更新のお知らせ」に出る）
- PR は squash でマージ。マージのときは head の SHA を40桁で指定する（短い SHA だと失敗する）
- マイグレーションは利用者が Supabase の SQL Editor で手で適用する。未適用でも画面が止まらないように作り、
  エラーでは `dbErrorMessage(err, "<ファイル名>.sql", ...)` でどのマイグレーションが要るかを出す
- 設定値（マイグレーション不要で保存したいもの）は `app_settings`（0149）に `getAppSetting` / `setAppSetting` で保存する
- 画面のサンプル画像を求められたら、ビルドの CSS（`.next/static/chunks/*.css`）を読む静的 HTML を作り、Playwright で撮って送る
- 利用者からもらったファイル（会社の情報が入った PDF など）は、リポジトリにコミットしない（安全チェックで止まる）。
  所属機関の添付ファイルなど、アプリの非公開ストレージに置いてもらう

### 引き継ぎ（「新規引き継ぎ作成」）のときの手順 — Obsidian への記録

利用者は作業の記録を Obsidian（iCloud の保管庫「AI共有」）にも残している。
「新規引き継ぎ作成」と言われたら、毎回次の順で進める（リポジトリ直下の `CLAUDE.md` にも同じ決まりを書いてある）。

1. リポジトリの引き継ぎ資料（`docs/` の handoff）を作って PR・マージする（これまでどおり）
2. 同じ内容を、利用者向けの言葉にした Obsidian 用のノートも必ず作る
   - ファイル名: `YYYY-MM-DD 入管アプリ 作業記録.md`（前回の引き継ぎからの作業をまとめる）
   - 先頭にプロパティ（title・date・tags: 入管アプリ／作業記録／特定技能・aliases）
   - 「まだ確認・対応が要ること」はチェックボックス（`- [ ]`）、マイグレーションの表、機能ごとの使い方、`[[入管アプリ]]` へのリンク
3. ノートのファイルを `SendUserFile` で送り、
   **「保管庫『AI共有』の『90_Inbox』フォルダにドラッグして入れてください」**と案内する
   - 保管庫の中のほかのファイル・フォルダは消さないよう、ひと言添える
   - 保管庫は ~/Library（iCloud）の中にあるため、Remote Control ではクラウドのセッションからつなげない（2026-11-10 に確認済み）。
     スイッチをオンにしてもらう必要はない
